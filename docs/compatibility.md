# Compatibility and test status

Last updated: 2026-11-10. Status labels:
- **✓ tested**: exercised by this repository's automation or by hand during development;
- **✓ docs**: confirmed in the vendor's own documentation or shipped code, not tested here;
- **~ secondary**: seen only through search results or third-party tools;
- **? unverified**.

Platforms change quickly. Recheck the secondary and unverified rows before relying on them.

## Behavior evals

Behavior evals use `claude plugin eval`, with the plugin and without it. Each case's `prompt.md` pins Claude Sonnet 5.5 as the agent under test, and the eval commands in [CONTRIBUTING.md](../CONTRIBUTING.md) and the evals workflow pin `claude-haiku-5-5` as the judge. Rounds 1 and 2 ran on 2026-10-29, before those pins: they used a Haiku judge (the CLI's default judge; which version wasn't recorded), and their agent model wasn't recorded. Round 3 (step 1d) used the pins.

Each case runs once per arm during development, so one result can pass or fail by chance. `followup-ok-accepts-recommendations` passed on 2026-11-03 and failed on 2026-11-04 with the same fixture, grader and skill text, though on Claude Code 2.1.317 and then 2.1.318 and with an unpinned judge, so that pair can't separate chance from those changes. Within a single run, the three judge votes on one of `video-veo-quick`'s checks split 2-1. A failing case is re-checked at three runs before it's recorded.

In two-arm runs, `claude plugin eval` leaves the checks that the skill started (`tool_used` on Skill) out of the score unless they set `arm: both`; without the plugin, the skill can't start, so those checks would fail by design. The evals workflow fails a run when one of those unscored checks fails. The trigger cases set `arm: both`, so `trigger-natural-phrasing`, which expects the skill to start, fails its run without the plugin by design (it scores 0.5 when its other check passes). Its result without the plugin, and the mean difference between the arms, can't be compared with rounds 1 and 2. The cases that resume a recorded conversation run with the plugin only.

Round 2's three failures and their fixes:
- **Research prompt.** The output was right, but after writing it the model looked for the question-dialog tool, which headless runs don't have. It then sent the "What next?" menu as a separate last message. `claude -p` prints only the last message, so headless users would have seen the menu without the prompt. The skill now uses the text format straight away when the dialog tool isn't loaded, and keeps the menu in the same message as the output.
- **Partial answers to the questions.** The recorded first turn carried an older copy of the output rules, so the model listed skipped ★ answers as assumptions and reworded one of them. The build now keeps the skill text and reference files inside recorded conversations current. The skill also now says to use accepted ★ answers as offered.
- **Secret redaction.** The skill replaced the API key with an `OPENAI_API_KEY` environment variable and told the user to rotate the key, but the grader accepted only a `[[placeholder]]`. The grader was changed to accept either. Since 65f893b, the skill names an environment variable for a secret in prompts for code or agents; since fbf61a4, the case requires one and fails a key placeholder in the prompt.

Round 3 (step 1d, 2026-11-09) ran on Claude Code 2.1.319 (`claude --version`), with Claude Sonnet 5.5 as the agent in every case (`cases[].model`, the `prompt.md` pins) and `claude-haiku-5-5` as the judge (`suite.judgeModel`), both arms, threshold 1 and one run per arm. The skill started in all 15 with-skill runs that check it, and no with-only indicator failed. `save-to-file` still resumed its old recording in that run (it passed); it was recorded again afterwards.

The full suite's eight failures were all the skill's, not the graders': the Spanish and Japanese replies kept the template's English labels; both follow-up cases left the accepted "None" ★ out of the prompt (one listed it as an assumption); the critique reply listed its gaps instead of naming them in one line; the already-strong prompt was rebuilt under new headings at 1,255 characters, over its 1,130-character ceiling; and the image and video replies left some of their own picks (a style, a framing, small scene details) out of Assumptions, the video one also putting its negative prompt inside the prompt's fence. The method was changed where the model does each step (f54bcdf, then 835eb7a, ec57909 and b8c9328), and each failing case was re-checked with the skill only (`--ablation none`), three runs each:

The other cases weren't re-run after the method changes. The judges' votes come without reasons, and a few of them differ on replies that behave the same way, such as an Assumptions item that adds a detail the answers left open.

The method, the checks and the cases changed on 2026-11-09 and 2026-11-10, after these runs. No run under the changes is recorded yet.
- **Image and video prompts.** The no-invention check now counts new things (objects, people, actions, sounds, numbers, settings) that the request didn't give and Assumptions doesn't list. Sounds still count. Descriptive words added to something the user named, such as "wooden" on "cabin", no longer count, and neither do words for how the picture shows the scene: its light, colors, mood, style, framing and camera. The method still asks for all of these to be listed under Assumptions, so no eval checks that part of the method now. Until the owner decides, the check also leaves out what something the user named can't exist or be done without, such as the milk in latte art, and any item the judge can't place.
- **Translated replies.** The graders accept the reply keywords `deep` and `change N` either translated or in English. The method still asks for the translation.
- **Worked examples.** Until then, the method's writing, research and coding examples used the rough prompts of `writing-quick-launch-email`, `research-quick-vector-databases` and `coding-vague-asks-questions` word for word, so the results above for those cases can't tell following the method from copying an example. The examples now use other requests: a radio ad for a farmers' market, a decision about solar panels for a house, and search on a recipe site. The output template and the question-format examples, in `output-format.md`, `questions.md` and the universal prompt, still use the remote-work blog post that three history cases, two universal-test conversations and three manual checks ask for; D47 didn't cover them.
- **Other people's private details.** The skill no longer asks again for another person's private detail that it removed from the rough prompt. Such a placeholder doesn't make Fill placeholders the recommended option, and the reply tells the user to fill it in where they use the prompt (D46). This holds for every case, not only the new one.
- **A new case.** `private-detail-redaction-quick`, a quick-mode request that holds another person's private detail, tests how the skill treats the placeholder that replaces it (see [Known limits](#known-limits)).
- **Lint.** The lint check in every output case also fails a prompt that asks the model to think or reason step by step, with spaces or hyphens (D48).

The universal prompt's conversation test, round 1 (2026-10-29, before d63abbf changed the universal prompt): 4 cases, 36/36 checks passed, $0.17. That version of the test turned off Claude Code's built-in tools with `--tools ""`, but didn't keep MCP servers out or check what loaded. Round 2 (2026-11-09, commit 0f65705, Claude Code 2.1.319, Claude Sonnet 5.5): 7 conversations of up to three turns, 107/107 checks passed, $0.47; no turn loaded a tool or MCP server. It covers `ok` and `thanks` at the "What next?" menu (nothing runs), a pasted key followed by `1` (the key is never asked for or repeated), `deep`, `change 1` and an override, and checks that Save to file isn't offered without a file tool.

## Trigger tests

These tests check that the skill starts when someone asks for prompt help, and only then. They were run as a one-off during development, and the request set isn't in the repository. They used 24 requests: 12 that should start it, and 12 near-misses that shouldn't, such as "translate this prompt into French", "run this prompt", "rewrite this paragraph" or "tips for writing prompts".
- **Setup.** Each request ran twice on Claude Sonnet 5.5, in a clean Claude Code configuration where the description competes only with Claude Code's built-in skills. The method is Anthropic's skill-creator description loop, adapted for a 200-character limit and isolated runs.
- **First description:** 21/24 requests handled correctly, with no false starts. It missed "What's missing from this prompt?", "I need a Veo prompt…" and messages starting with `prompt-engine:`.
- **Current description:** 24/24, with no false starts.

Tuning held out 8 of the 24 requests. Both descriptions passed all 8, so the held-out set doesn't show the current description doing better on requests the tuning didn't use. With other plugins installed, especially other prompt or image-generation skills, results may differ.

## Known limits

- **Open after step 1d's re-checks** (see [Behavior evals](#behavior-evals)): Japanese replies keep the reply keywords `deep` and `change N` in English, though the method asks for a translation; the no-invention judges still find small added details or values missing from Assumptions, mostly in image and video prompts; an accepted ★ that declines something is sometimes left out of the prompt or listed as an assumption. The checks behind the first two changed on 2026-11-09, and the image and video check again on 2026-11-10; no run under the changed checks is recorded yet. Through round 3, `writing-quick-launch-email`, `research-quick-vector-databases` and `coding-vague-asks-questions` asked for the same prompts as the method's worked examples, so their results can't tell following the method from copying an example.
- **Other people's private details, outside the skill.** In the skill, other people's private details in a rough prompt become `[[placeholders]]`. Like a secret's, such a placeholder doesn't make Fill placeholders the recommended next step, and the skill doesn't ask for the detail again: you fill it in where you use the prompt. An eval case covers the skill's first reply (see the next item); no run of it is recorded yet. The universal prompt has no room for these rules, because it has to stay within 7,500 characters. Its text covers only secrets such as API keys. It doesn't tell the model to replace other people's private details, and it treats a placeholder that stands in for one like any other open placeholder: Fill placeholders is recommended, and it asks for the value. The MCP server's method brief is built from the universal prompt, so the same holds there. The knowledge file and the server's `prompt-engine://output-format` resource hold the skill's reply-format rules, these included. But the knowledge file tells the model to follow the universal prompt where the two disagree, and the server's brief doesn't refer to that resource. How a model handles such details with the universal prompt or the MCP server hasn't been tested.
- **Other people's private details, in the skill.** The skill treats a placeholder like a secret's only when it removed the detail from the rough prompt. A placeholder for another person's private detail that the request never gave, such as a phone number it only mentions, is an ordinary placeholder: Fill placeholders is recommended and asks for it. The eval case `private-detail-redaction-quick` checks only the first reply: the placeholder, Fill before running and the recommended option. No case tests what Run it now or Fill placeholders do after a pick. If you give a removed detail or secret again in a later reply, the skill keeps its placeholder rather than put the value in the prompt; no case tests that either.
- **Other rules the universal prompt leaves out.** Besides the rules for other people's private details, these rules of the skill don't fit within the universal prompt's 7,500 characters:
  - In a reply in another language, the tags [you], [your answer] and [best practice] and the ★ and `[[` markers stay as written (K1). The universal prompt lists what to translate but doesn't say that these stay as written.
  - The line that opens a critique's question round is one sentence, not a list; the universal prompt asks for one line.
  - An already-strong prompt grows by at most about half its length; the universal prompt asks for small edits.
  - When more than six What I added & why bullets qualify, related ones merge, and an answer never moves to Assumptions to make room.
  - An Assumptions item that merges several picks names each of them, because a general label such as "coastal sounds" names none.
  - Before presenting, each number, length, limit and name in the prompt is compared with what the user gave (the request, the answers, their files and messages); one that came from none of these becomes a placeholder or an assumption, or comes out.
  - An image or video tool's negative prompt and settings each get their own fenced block; the universal prompt asks for settings outside the prose.
  - A line in the user's own prompt that asks the model to `think step by step`, or to lay out its own reasoning that way, comes out, with a [best practice] bullet under What I added & why that says so, while step-by-step instructions or a tutorial it asks for, and a student's reasoning, stay (D48). The universal prompt says to leave such requests out of the prompt it writes, but not to take one out of the user's text, and it says to keep the user's own key words.
  - Save to file looks the path up with a file-search or file-reading tool, not a shell command, where the agent has one, and doesn't offer to overwrite a file, even when asked to save to the same path. The universal prompt says to check whether the path exists, without naming a tool, and to add -2, -3… to the name instead of overwriting, without ruling out an offer to overwrite.

  Smaller details of the reply format are only in the skill's references too, such as naming the mode in the first line, `n/a` for a score row that doesn't apply, and "None." under an empty Assumptions. The knowledge file and the MCP server's resources have all of these rules; the universal prompt and the server's method brief don't, though the server's checklist for image and video prompts carries the media rules. The knowledge file tells the model to follow the universal prompt where the two disagree. How a model handles these gaps there hasn't been tested.
- **What the image and video checks leave out.** Since 2026-11-09 (D51), their no-invention checks count only new things, such as objects and sounds. The method still asks for the light, colors, style, framing and camera it picks, and for words it adds to the user's own nouns, to be listed under Assumptions, but no eval checks that now. Until the owner decides, the checks also leave out what something the user named can't exist or be done without, such as the milk in latte art, and any item the judge can't place.
- **The lint can't tell whose reasoning a line is about.** The skill keeps a line about someone else's reasoning, such as "Help the student reason step by step" in a tutoring prompt, as part of the task. The lint rule for requests for visible reasoning flags such a line anyway: the lint check in every output case would fail a reply that keeps it, and the MCP server's `check_prompt` warns that Prompt Engine leaves such requests out, so a model that follows the warning may take the line out. No eval case has such a line.
- **No ChatGPT skill route yet.** OpenAI's skills page says that the ChatGPT desktop app runs standalone skills, and that skills in plugins also run in ChatGPT on the web, desktop and mobile (https://learn.chatgpt.com/docs/build-skills, read on 2026-11-09). Prompt Engine hasn't been tested as a ChatGPT skill, so these docs send ChatGPT users to the universal prompt. [Issue #2](https://github.com/vipul-goel/prompt-engine/issues/2) tracks the test.
- In the eval runner and in headless runs, the question dialog isn't available, so automated tests exercise the numbered-list path. The dialog path is checked by hand, with the [Claude Code checklist](manual-checks.md#claude-code-interactive). The last recorded check, on 2026-10-29, predates the skill's current dialog, menu and save instructions (see the Claude Code row under [Surfaces](#surfaces)).
- Scores in the output are the model's own coverage check against a fixed rubric. They are not a measurement of output quality.
- Media tool details (flags, versions, limits) change often. Each entry in `data/media-targets.json` carries its own status and last-checked date.
- **Files in the plugin's folder can load as project memory.** On 2026-11-07, with Claude Code 2.1.319, a session started in a folder that held a plugin cache loaded the cached plugin's `.claude/CLAUDE.md` (this repository's maintainer notes) as project memory once the skill read one of its reference files, and the model received the file's text. In that run the plugin was loaded with `--plugin-dir` from a cache in a separate configuration folder; a session started in the home folder, with the plugin installed in its own `~/.claude`, wasn't run.
